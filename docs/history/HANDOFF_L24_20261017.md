## 5. Metodo operativo

1. **Preflight** — `state.py` e `check_handoff.py` devono uscire **0**. Se no, §5.0.
2. **Misura** — `next_section.py` propone un confine; deve cadere **fra due contesti** (fine
   missione/dialogo), mai dentro. Se è illegittimo, prendere il primo confine valido e documentarlo.
3. **Export** — `export_section.py` in una directory **nuova** (lo strumento esce 2 se esiste già).
4. **Ricognizione** — leggere `kind` e `raw`: un tipo mai visto si decide guardando la riga nel file.
5. **`check.py`** — copiarlo dal lotto precedente e adattare percorso, numero di unità, `NT`,
   `TOKEN_EXC` (se ci sono pronomi-token), `TITLES`.
6. **Tradurre a parti** (60–100 unità) in `parts/partNN.json`, forma `{"1": "…", …}`; dopo **ogni**
   parte `check.py --range A B` e risoluzione di **tutti** i FAIL.
7. **Rilettura** — i controlli non certificano la lingua: rileggere l'italiano della parte.
8. **Chiusura** (§10) solo a lotto completo.

### 5.0 Se il preflight fallisce

Non correggere il documento per farlo passare. Determinare **quale dato è cambiato** confrontando
`state.py` con §3, verificare il workspace, aggiornare il documento **solo** se le nuove misure lo
giustificano. Un `check_handoff.py` rosso significa che il documento è disallineato, non che il
progetto è rotto.

## 6. Riferimento degli strumenti

Tutti in `staging/editorial/tools/`, invocati con `python`, dalla root del progetto.

| strumento | cosa fa | quando |
|---|---|---|
| `state.py` | staging per file, totali, residuo, hash e integrità dei file protetti | preflight, dopo ogni chiusura |
| `next_section.py <file> <da> <min> <max>` | propone un segmento (righe, unità, parole, contesti, tipi, token) e il confine successivo | prima di ogni export |
| `export_section.py <dir> <file> <da> <a> [nota]` | crea il lotto e `source.json`, stampa la ricognizione | una volta per lotto |
| `check_handoff.py` | confronta questo documento col workspace (26 controlli) | preflight e dopo ogni aggiornamento |
| `<lotto>/check.py [--range A B]` | controlli strutturali, rigenera `translation.json` | dopo ogni parte e a lotto chiuso |
| `<lotto>/verify.py` | controlli **indipendenti** (riga grezza, DB, copertura, token, parti) | solo a lotto chiuso |

### 6.1 `state.py`

Stampa per ogni file unità tradotte/totali, percentuale, parole EN→IT, numero di lotti; poi
`TOTALE staging`, il residuo traducibile e un blocco di integrità che deve chiudersi con `ESITO: OK`.
Se un hash non corrisponde, **fermarsi**: un file protetto è cambiato.

### 6.2 `check.py`

Controlla: copertura dell'intervallo e del lotto; traduzioni vuote; unità `NT` identiche; duplicati
italiani non spiegati dal sorgente; tab / tab iniziale / virgolette / backtick per unità; token `<…>`;
spazi iniziali e finali; doppi spazi; rapporto lunghezza (0,55–1,90) con `OUTLIER` stampati;
tipografia (accento sostitutivo, ellissi, em dash, apostrofo curvo); caratteri non latini; parole
inglesi residue (con `TITLES` e rimozione dei token); stato del database (APPROVED 364, ultimo
aggiornamento, unità del lotto tutte `PENDING`).

`--range A B` limita i controlli all'intervallo; i due controlli di **copertura** restano FAIL finché
il lotto non è completo: è normale.

### 6.3 `verify.py`

Indipendente da `check.py`. Verifica almeno: riga grezza identica al file; `english`/`kind`/`path`
identici al DB; tutte `PENDING`; nessuna `APPROVED`; id univoci; ordine = sorgente; intervallo di
righe e file completo; copertura dello staging su quel file; `NT` identiche; token (parità esatta o
sole eccezioni dichiarate); tab/virgolette/backtick; nessun italiano vuoto; nessun carattere non
latino; rapporti definiti; ricostruzione di `translation.json` dalle parti. Esce 0 o 1.

### 6.4 `check_handoff.py`

Estrae i numeri **da questo documento** e li confronta col workspace: totali di staging, copertura per
file, numero di directory, `APPROVED/PENDING`, label non traducibili, residuo, tabella del lotto
attivo (righe, unità, parole, contesti, tab/virgolette, confine), hash citati e `b4aa3bac3`. Esce 1 se
un numero dichiarato manca o non coincide: non si «passa» omettendo un dato. Le celle numeriche devono
contenere **solo** il numero (niente note nella stessa cella).

### 6.5 `dump_section.py` (helper esterno, fuori dal repo)

Stampa le unità di un intervallo in forma non ambigua (JSON-escaped), raggruppate per contesto:
`idx<TAB>kind<TAB>"testo inglese"`. Se il file manca, ricrearlo così:

```python
"""dump_section.py — stampa le unita' di una sezione in forma non ambigua (JSON-escaped)."""
import json
import sys

d, a, b = sys.argv[1], int(sys.argv[2]), int(sys.argv[3])
src = json.load(open(d + '/source.json', encoding='utf-8'))
sel = [u for u in src['units'] if a <= u['idx'] <= b]
print('# unita %d-%d di %d | contesti: %s' % (a, b, len(src['units']),
      ', '.join(dict.fromkeys(u['context'] for u in sel))))
cur = None
for u in sel:
    if u['context'] != cur:
        cur = u['context']
        print('\n=== %s (riga %d) ===' % (cur, u['line']))
    print('%d\t%s\t%s' % (u['idx'], u['kind'], json.dumps(u['english'], ensure_ascii=False)))
```

## 10. Chiusura di un lotto — procedura completa

Solo quando tutte le unità sono tradotte (o `NT`) e `check.py` è verde sull'intero lotto.

1. **`check.py` completo** → `FAIL totale: 0`.
2. **`verify.py`** — scriverlo per quel lotto (copiando dal precedente e adattando `PATH`, `NT`,
   `TOKEN_EXC`, offset attesi), eseguirlo: exit **0**. Deve essere indipendente, non una copia dei
   controlli di `check.py`.

## 14. Quando ci si ferma (fine sessione, cambio modello, blocco)

1. Scrivere su disco l'ultima parte tradotta e far passare `check.py --range` su quella parte.
2. Aggiornare `staging/editorial/L24_<data>/STATO.md`: parti fatte, unità, parole, ripresa
   (unità + riga + contesto), decisioni nuove, regole nuove.
3. Aggiornare **questo** documento: §3 (totali), §4 (punto di ripresa), §11 (attesi).
4. Aggiornare `CHECKPOINT_EDITORIALE.md` §4.2/§4.3/§8 con le stesse cifre.
5. Rilanciare `state.py` e `check_handoff.py`: entrambi **exit 0**.
6. Nel messaggio finale dichiarare: dove ci si è fermati, cosa è verde, cosa **non** è verificato.

Un checkpoint che non passa `check_handoff.py` non è un checkpoint: è un documento che mente.
