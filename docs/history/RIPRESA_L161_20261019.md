## 1. Mandato e regole non negoziabili

Si traduce in **italiano** *Endless Sky* (testi sotto `data/`), **a lotti**, dentro `staging/editorial/L<n>_<data>_<ora>/`.
Ogni lotto si chiude con **due script indipendenti a exit code** e con i documenti.

1. **Lo staging non è approvazione**: nessuna scrittura su `state.db`, nessun caricamento nel gioco, nessun commit nel
   repo originale.
2. **Un'unità `APPROVED` non si riscrive**: si riproduce **alla lettera** dal campo `italian` del database.
3. **I numeri si misurano**, mai si deducono. Ogni misura scritta in un documento deve venire da un comando eseguito in
   quella sessione.
4. **Le asserzioni vuote si scrivono** (`== []`, `== {}`): «niente da controllare» e «controllo mancato» devono
   distinguersi.
5. **Un controllo che non può fallire non è un controllo** (`ck(..., True)`): si toglie.
6. **Si corregge la resa, non il controllo**, quando il gate di lunghezza (0,55–1,90) o la tipografia bocciano un testo.
7. **`UI_LABEL`, `VALUE` e chiavi `Preferences` non si traducono**; le virgolette di **dialogo** sì, unità per unità.
8. **I nomi propri restano inglesi**: navi, armi, moduli, specie, mondi. **Fazioni e regioni invece si traducono**
   (`Syndicate` → Sindacato, `Southern Rim` → Bordo Meridionale).
9. **Registro unico «tu»** per il giocatore; la cortesia «Lei» si corregge.
10. **Un documento superato si marca `OBSOLETO`**; un handoff nuovo diventa il contratto attivo.

## 5. Metodo per lotto (7 passi, nell'ordine)

1. **Preflight**: `python staging/editorial/tools/state.py` → `ESITO: OK`, `INTEGRITA'` pulita, residuo coerente.
2. **Export**: `export_section.py <directory> <percorso> <riga_da> <riga_a>` (**directory prima del percorso**).
3. **Stati e forma**: contare `APPROVED`/`PENDING`, `Counter(kind)`, contesti, tab, virgolette, token; **asserirli**.
4. **Traduzione** in `parts/partNN.json`, **senza tab iniziali** (li antepone il costruttore).
5. **`check.py`**: costruisce `translation.json` e verifica tipi, tab, virgolette, token, contesti, gate, tipografia,
   cortesia, stato `PENDING`.
6. **`verify.py` indipendente**: ricalcola dal **database** riga grezza, `english`/`kind`/`context`, unità prima e dopo,
   il confine, e usa l'**invariante di file** se il lotto chiude il file.
7. **Documenti**: `STATO.md`, `REPORT.md`, `review.md`; `HANDOFF_L<successivo>.md`; patch dei checkpoint; batteria §7.

## 6. Trappole che contano adesso

1. **Un token si verifica per simbolo e per unità**: due segnaposto scambiati danno lo stesso totale. Serve l'ordine
   per unità (qui i token sono **zero**: la verifica è `== {}`).
2. **Articolo davanti a nome inglese con H iniziale: «il»** («il Heavy Blaster», «il Heavy Rocket Rack»). Scelta del
   batch L154–L160, applicata in 3 lotti: non cambiarla senza rigenerare quelli.
3. **`VALUE` restano inglesi** e vanno verificati uno per uno; il controllo dei residui inglesi **li esclude**.
4. **Le copie si verificano come copie**: se due unità hanno lo stesso inglese, la resa deve essere identica — e se una
   stringa esiste in un lotto precedente, si confronta con quella **già scritta** (L157/L158/L159/L160 lo fanno).
5. **Un prefisso non è un'uguaglianza**: la frase di apertura di un testo lungo va verificata con `startswith`.
6. **Ellissi e trattino**: il `...` del sorgente resta tre punti ASCII e il ` - ` resta un trattino semplice; `…`, `—`,
   `–`, `’`, `«»` fanno fallire la tipografia.
7. **`check_handoff.py` è a contratto**: celle `Contesti` in forma **bare** (senza prefisso), `Confine dopo` con il
   contesto **grezzo** se non è «fine file» (`riga 112 apre \`outfit:Cryogenic Deuterium Tank\``), totali, residuo,
   hash e `sha` del lotto presenti.
8. **Il numero di controlli si conta sull'output** (`FAIL: 0 / N`), non si dichiara.
9. **Un indice sbagliato costa tre script**: gli indici delle unità (tab, virgolette, duplicati) si leggono dal
   `source.json`.
10. **Un controllo può essere sbagliato quanto una resa**: nel batch sono stati corretti 4 controlli (tema
    «cannone/cannoni», «complete with» vs «completo di», «munizion-», conteggio dei testi distinti) e **nessuna
    resa** per farli passare. Se un controllo fallisce, prima si legge l'output.
11. **La write-guard rifiuta la sovrascrittura** di un file letto in modo paginato: si usa `patch`, o si rigenera.
12. **L'elenco completo delle trappole** sta in `CHECKPOINT_SESSIONE_20261018.md` §7. Se il lotto ne scopre una nuova,
    si aggiunge **là**.

## 7. Definizione di «fatto» e batteria finale

Un lotto è chiuso quando, **nello stesso turno**:

```bash
# 1. i due script del lotto
python staging/editorial/L161_*/check.py      # atteso: "FAIL totale: 0"  (exit 0)
python staging/editorial/L161_*/verify.py     # atteso: exit 0

# 2. i documenti a contratto
python staging/editorial/tools/check_handoff.py HANDOFF_L162_20261019.md
python staging/editorial/tools/check_handoff.py CHECKPOINT_SESSIONE_20261018.md
python staging/editorial/tools/check_handoff.py CHECKPOINT_AGENTE_SESSIONE_20261018.md

# 3. la batteria completa: ogni verify.py deve dare exit 0
for f in staging/editorial/L*/verify.py; do python "$f" >/dev/null 2>&1 || echo "ROSSO $f"; done

# 4. stato e integrità
python staging/editorial/tools/state.py        # "ESITO: OK", INTEGRITA' tutta OK

# 5. il repo originale non si tocca
git -C ../endless-sky status --porcelain       # atteso: vuoto
```

e quando sono veri **tutti** questi punti:

- [ ] `check.py` → `FAIL totale: 0` e `verify.py` → **exit 0**;
- [ ] tutte le unità del lotto sono **`PENDING`** nel database (asserito, non supposto);
- [ ] token, tab, virgolette e ripetizioni **pari per unità**, non solo nei totali;
- [ ] se il lotto chiude il file: **somma dei lotti = totale del file**, `max(line)`, zero sovrapposizioni;
- [ ] `STATO.md`, `REPORT.md`, `review.md` scritti con i numeri **misurati in quel turno**;
- [ ] `HANDOFF_L<successivo>.md` verificato da `check_handoff.py` (`FAIL: 0`);
- [ ] i checkpoint aggiornati (CRLF preservato, sostituzioni per **span di heading**, marker idempotente);
- [ ] l'handoff superato marcato **`OBSOLETO`**;
- [ ] batteria: **162/162** `verify.py` verdi (oggi; 163 dopo L161), `state.py` `ESITO: OK`, repo pulito.

**Livelli di risultato** (da dichiarare sempre con la parola giusta):

| livello | cosa lo dimostra |
|---|---|
| IMPLEMENTATO | gli script esistono e il codice è scritto |
| ESEGUITO | gli script sono stati lanciati e l'output letto |
| **VERIFICATO** | exit code 0 **e** asserzioni che potevano fallire |
