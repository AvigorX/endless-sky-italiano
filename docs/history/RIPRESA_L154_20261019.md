## 5. Metodo per lotto (7 passi, nell'ordine)

1. **Preflight**: `python staging/editorial/tools/state.py` → `ESITO: OK`, `INTEGRITA'` pulita, residuo coerente.
2. **Export**: `export_section.py <directory> <percorso> <riga_da> <riga_a>` (**directory prima del percorso**). Stampa
   tipi, tab, virgolette, token: è la ricognizione da cui si prendono le attese.
3. **Stati e forma**: contare `APPROVED`/`PENDING`, il `Counter(kind)`, i contesti, i tab, le virgolette, i token;
   **asserirli** nel costruttore.
4. **Traduzione** in `parts/partNN.json`, **senza tab iniziali** (li antepone il costruttore, contati dal sorgente).
   Nei lotti ripetitivi si usa una **mappa `(kind, english) → italiano`**: due copie dello stesso testo non possono
   divergere.
5. **`check.py`**: costruisce `translation.json` e verifica tipi, tab, virgolette, token, contesti, gate, tipografia,
   cortesia, stato `PENDING` di ogni unità.
6. **`verify.py` indipendente**: ricalcola dal **database** riga grezza, `english`/`kind`/`context`, il numero di unità
   prima e dopo, il confine, e usa l'**invariante di file** se il lotto chiude il file.
7. **Documenti e checkpoint**: `STATO.md`, `REPORT.md`, `review.md` nel lotto; `HANDOFF_L<successivo>.md`; patch dei tre
   `CHECKPOINT_*`; poi la **batteria finale** (§7).

## 6. Trappole che contano adesso

1. **Un token si verifica per simbolo e per unità**: due segnaposto in unità diverse danno un totale pari anche se
   scambiati. Con due simboli dallo stesso conteggio il multiset è **cieco**: serve l'ordine per unità.
2. **`<destination>` ≠ `<planet>`**: destinazione di missione contro mondo di consegna; si verificano anche le **assenze
   incrociate**.
3. **«Quasi la stessa frase» non è la stessa frase**: `on <planet>` e `on the <planet>` sono due stringhe, e la resa
   cambia («su» / «sul»). Il riuso si fa **solo** con la chiave inglese identica.
4. **I `VALUE` restano inglesi** (nomi di lavoro, missione, inizio, nave) e vanno verificati uno per uno; il controllo
   dei residui inglesi **li esclude**, altrimenti si contraddice.
5. **Un token-suffisso si incolla al nome** (`Hai<hood>`), un token a inizio frase regge la maiuscola che segue; un
   segnaposto che contiene una frase (`<The engineer>`) si confronta **esatto**, mai con `.lower()`.
6. **Un token con parentesi si confronta intero**: `<as before (run)>` non si spezza.
7. **Le virgolette aperte dal sorgente non si chiudono**: disparità riprodotta, nessuna virgoletta finale aggiunta.
8. **L'inversione di Arach e Saryd si conserva** («Enormemente prezioso è…»): è la voce della specie, non un errore.
9. **`on site` / `on the site`** → «sul posto» / «sul luogo»: rese **diverse**, verificate come diverse.
10. **Un file può avere inventario vuoto di testo**: `data/human/news.txt` ha **164 unità su 202** che sono il
    delimitatore `` `"` ``, e **1.356 righe** con una frase quotata assenti dal database. Prima di aprire un lotto si
    verifica che le unità siano **testo**, non punteggiatura: il file con più unità residue non è il prossimo.
11. **`check_handoff.py` è a contratto**: la cella `Contesti` vuole la forma **bare** (senza prefisso), `Confine dopo`
    vuole `riga N apre \`X\`` oppure **«fine file»**, e devono esserci i totali, il residuo, gli hash, il `sha` del lotto.
12. **Il numero di controlli si conta sull'output** (`FAIL: 0 / N`), non si dichiara.
13. **Un'indice sbagliato costa tre script**: gli indici delle unità (tab, virgolette, DIALOG) si leggono dal
    `source.json`, non si scrivono a memoria.
14. **La write-guard rifiuta la sovrascrittura** di un file letto in modo paginato: si usa `patch`, oppure si rigenera il
    file da zero.
15. **L'elenco completo delle 89 trappole** sta in `CHECKPOINT_SESSIONE_20261018.md` §7: qui ci sono quelle che servono
    per L154. Se il lotto ne scopre una nuova, si aggiunge **là** (e la si riporta qui solo se è strutturale).

## 7. Definizione di «fatto» e batteria finale

Un lotto è chiuso quando, **nello stesso turno**:

```bash
# 1. i due script del lotto
python staging/editorial/L154_*/check.py      # atteso: "FAIL totale: 0"
python staging/editorial/L154_*/verify.py     # atteso: exit 0  (echo "exit=$?")

# 2. i documenti a contratto

python staging/editorial/tools/check_handoff.py CHECKPOINT_AGENTE_SESSIONE_20261018.md

# 3. la batteria completa: ogni verify.py deve dare exit 0
for f in staging/editorial/L*/verify.py; do python "$f" >/dev/null 2>&1 || echo "ROSSO $f"; done

# 4. stato e integrità
python staging/editorial/tools/state.py        # "ESITO: OK", INTEGRITA' tutta OK

# 5. il repo originale non si tocca
git -C ../endless-sky status --porcelain       # atteso: vuoto
```

e quando sono veri **tutti** questi punti:

- [ ] `check.py` → `FAIL totale: 0` e `verify.py` → **exit 0**;
- [ ] tutte le unità del lotto sono **`PENDING`** nel database (asserito, non supposto);
- [ ] token, tab, virgolette e ripetizioni **pari per unità**, non solo nei totali;
- [ ] se il lotto chiude il file: **somma dei lotti = totale del file**, `max(line)`, zero sovrapposizioni;
- [ ] `STATO.md`, `REPORT.md`, `review.md` scritti con i numeri **misurati in quel turno**;
- [ ] `HANDOFF_L<successivo>.md` verificato da `check_handoff.py` (`FAIL: 0`);
- [ ] i tre checkpoint aggiornati (CRLF preservato, sostituzioni per **span di heading**, marker idempotente);
- [ ] l'handoff superato marcato **`OBSOLETO`**;
- [ ] batteria: **155/155** `verify.py` verdi (oggi; 156 dopo L154), `state.py` `ESITO: OK`, repo pulito.
